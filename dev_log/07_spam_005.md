# Subunit 7.5: URL Validation and Publishing Delay

## Objective

Add a 12-hour delay before publishing articles and validate URLs before posting to prevent publishing spam articles that AWS removes from their feed.

## Problem

AWS Builder is removing spam articles from their feed after they're published. Our bot fetches these articles immediately and posts them to Twitter, but by the time they're posted, AWS has already removed them, resulting in broken links on Twitter.

## Solution

Implement a two-layer protection:
1. **12-hour delay**: Wait 12 hours after fetching an article before attempting to publish it
2. **URL validation**: Before publishing, verify the article URL returns HTTP 200 status
3. **Auto-spam marking**: If URL returns 404/400 or fails, mark article as spam automatically

## Implementation Plan

### Changes to `get_next_article()`

**Current behavior:**
```python
SELECT * FROM articles 
WHERE posted = 0 AND is_spam = 0
ORDER BY published_at ASC 
LIMIT 1
```

**New behavior:**
1. Query articles where `fetched_at <= (now - 12 hours)`
2. Get top 10 candidates (not just 1)
3. For each candidate, check URL with HTTP HEAD request
4. If status == 200: return article for posting
5. If status != 200 or error: mark as spam, try next candidate
6. If no valid articles found: return None

### Technical Details

**Time calculation:**
- Use `fetched_at` column (already exists, stores milliseconds since epoch)
- Calculate: `twelve_hours_ago = current_time_ms - (12 * 60 * 60 * 1000)`
- Filter: `WHERE fetched_at <= twelve_hours_ago`

**URL validation:**
- Use `httpx.head()` for efficiency (no body download)
- Set timeout: 10 seconds
- Follow redirects: `follow_redirects=True`
- Accept only status code 200

**Auto-spam marking:**
- Create helper function: `mark_article_spam(content_id)`
- Updates: `UPDATE articles SET is_spam = 1 WHERE content_id = ?`
- Log the action for monitoring
